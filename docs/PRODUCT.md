# Noesis 제품 요구사항

상태: **UI 프로토타입 · 실제 데이터/분석/인증 연결 전**. 최종 갱신: 2026-11-11.

## 제품 방향

국내 주식을 대상으로 공시·뉴스·차트를 함께 살피고, 투자 기간별 판단과 이유를 확인하는 서비스다.
초기에는 소수 사용자에게 무료로 제공하며, 모바일 사용을 우선한다. 초기 PWA와 이후 모바일 앱을 목표로 하나 설치·푸시는 아직 구현하지 않았다.

초보자는 판단에 필요한 정보를 이해하고, 경험자는 자신의 판단을 보조하면서 자료 확인 시간을 줄인다.
핵심은 종목 분석부터 판단까지이며, 뉴스·공시 탐색은 이를 돕는 부가 기능이다. 부가 기능도 첫 버전의 필수 범위에 포함한다.

## 첫 버전 범위

| 영역 | 요구사항 | 현재 상태 |
| --- | --- | --- |
| 종목 탐색 | 종목명·코드 검색, 거래대금·거래량 정렬, 업종 구분 | 8종목 예시 UI |
| 시장 범위 | KOSPI200 밖의 국내 상장 종목까지 확대 | 종목 마스터·증권 유형·자료 지원 범위 확인 필요 |
| 관심 종목 | 사용자별 저장 및 기기 간 이어보기 | 브라우저 저장만 구현 |
| 시세·차트 | 현재가·등락률·관측 시각, 가격·거래량 차트 | 합성 일봉. 분봉/틱/실시간은 공급처 검증 후 |
| 분석 요청 | 사용자가 요청한 시점의 자료로 종목별 분석 | 예시 진행 화면과 결과 |
| 결과 | 단기·중기·장기 판단과 핵심 이유, 필요한 분석 상세 펼치기 | 예시 결과. 정확한 기간 경계 미정 |
| 분석 이력 | 당시 결과·입력 기준 시점 저장, 재진입 시 같은 결과 읽기 | 고정 예시와 페이지 메모리 |
| 뉴스 | 상단 주요 뉴스와 카테고리별 일반 뉴스, 변화의 AI 해설 | 예시 기사와 화면 순환 |
| 공시 | 주요 일정, 주요/전체 공시, 관심 종목 필터, 정정·철회 구분 | 예시 일정/목록 |
| 회원 | 이메일 가입·인증, 카카오·Google·네이버 로그인 | 실제 인증 없는 UI 흐름 |
| 내 정보 | 프로필, 최근/전체 분석, 관심 종목, 알림·계정 설정 | 예시 계정·설정 |
| 보유 현황 | 개인 보유 종목을 가져오는 방식 | 직접 입력·계좌 연동 모두 후속 검토 |

## 분석과 저장 원칙

1. 요청형 분석을 사용한다. 화면 조회·검색·관심 종목 저장은 새 분석 요청이 아니다.
2. 결과를 다시 열 때 당시 결과를 읽는다. 진행 중 요청 중복과 같은 자료에 대한 결과 목적 재시도를 막는다.
3. 사용자 공통 종목 판단으로 시작한다. 개인화는 적법한 자료 연결 및 별도 설계 후 검토한다.
4. 매수·관망·자료 부족을 구분한다. 자료 일부 누락과 기준 시각을 함께 표시한다.
5. 단기·중기·장기 판단을 각각 제공한다. 기간의 경계와 판단 기준은 실제 파이프라인 구현 전 확정한다.
6. 원문 출처를 상세 탐색하는 화면은 보류했으나 내부 원자료 식별자·시각·분석 버전 기록은 필요하다.
7. 이름과 이메일 문자열만으로 다른 로그인 계정의 기록을 합치지 않는다.

## 뉴스 갱신 정책 — 연결 전

- 뉴스 자료는 **5분마다** 새 항목을 확인하는 정책이다.
- 새 기사나 중요한 정정을 받으면 주요 뉴스를 다시 평가한다.
- 새로운 사건이나 중요한 내용 변화가 있을 때만 공용 AI 해설을 생성한다.
- 주요 뉴스 배너는 **6초마다** 다음 항목을 표시한다. 이 화면 전환은 수집·분석 호출이 아니다.
- 주요 뉴스와 동일 사건은 아래 일반 뉴스 목록에서 중복 노출하지 않는다.
- 장중 브리핑과 장마감 요약을 별도 화면으로 나누지 않는다.
- 확인된 사실과 AI의 가능한 설명을 구분한다. 가격 변화의 원인이 확인되지 않으면 단정하지 않는다.

현재 프로토타입에서는 배너의 화면 전환만 실행된다. 스크래핑/API·중요도 판별·AI 해설·수집 스케줄러는 없다.

## 계정·보유 현황

로그인 순서는 이메일 폼 → 카카오 → Google → 네이버다. 가입/비밀번호 찾기/인증 완료 흐름은 예시다.
실제 인증 제공자 조합, 계정 연결·탈퇴·보존 정책, DB와 푸시 채널은 구현 전에 정한다.

보유 현황 직접 입력은 UX 문제로 보류했다. 증권사 계정·쿠키·개인 API 키를 받아 우회 연동하지 않는다.
공식 위임/제휴 경로의 허용 범위와 비용을 확인한 다음 보유 현황 기능을 다시 설계한다.

## 초기 사용성 확인

- 검색 → 시세·차트 → 분석 요청 → 기간별 결과 → 분석 상세 흐름을 휴대폰에서 수행한다.
- 관심 목록과 분석 이력을 다시 찾을 수 있는지 확인한다.
- 관망·판단 불가·자료 일부 누락을 사용자가 구분할 수 있는지 확인한다.
- 응답 속도는 실제 종목 분석을 연결한 후 측정한다. 아직 목표 지연시간이나 월 비용을 확정하지 않았다.
- 수익률을 UI 또는 서비스 완성의 근거로 제시하지 않는다.

분석 제공 방식은 다중 사용자 서비스 이용 가능 여부와 비용을 확인한 뒤 구현한다.
개인 구독의 서비스 제공 가능 여부가 검증됐다고 가정하지 않는다.
